Rule Fidelity

Competitive standard enforcement

This implementation follows standard English draughts rules used in organized play, where captures are compulsory and capture sequences must be completed once started.

Many online implementations and student projects relax or omit these constraints entirely, allowing illegal non capture moves or premature turn endings.

Official rule sets explicitly require forced captures and complete multi jump sequences. This project treats rule enforcement as a correctness problem, not a UX convenience.

From Scratch Game Engine

No external engines or libraries

The game engine is implemented entirely from scratch. No checkers engines, no chess engines, no move generation libraries, and no rule abstractions.

Board state representation, legal move generation, forced capture enforcement, capture chaining, king promotion, and terminal state detection are all explicitly coded.

Most academic implementations rely on prebuilt engines or simplified logic that bypasses rule complexity. This project intentionally does not, in order to expose the full decision surface to the AI.

Search and AI Design

Minimax with alpha beta pruning

The AI opponent uses a classical minimax search with alpha beta pruning over explicitly generated legal game states.

Search depth is intentionally capped to balance responsiveness with strategic pressure, emphasizing evaluation quality over brute force.

The goal is not to create an unbeatable agent, but to model decision making under constrained computation, mirroring real world AI tradeoffs.

Academic Context and Intent

Problem Solving with AI at Minerva

Built for Problem Solving with AI at Minerva University.

The assignment objective was to implement a decision making agent using classical search techniques. This project exceeds the minimum requirements by enforcing full rule correctness and implementing a complete game engine.

The focus is on modeling state, constraints, and tradeoffs, not just producing a playable result.
